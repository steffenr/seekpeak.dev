# Glossary

| Term | Definition |
|------|------------|
| **Peak / Peak time** | Time window during which DeepSeek API requests are billed at 2x the off-peak rate. |
| **Off-peak** | All hours outside peak windows; requests billed at the base rate. |
| **UTC** | Coordinated Universal Time. The single clock on which peak/off-peak verdict is computed. |
| **Peak window** | A half-open `[start, end)` interval in UTC: `01:00–04:00` and `06:00–10:00`, applied Monday–Friday. |
| **Verdict** | The boolean "is now peak or off-peak" — identical for every visitor at a given instant because it is computed on UTC now. |
| **Transition** | The next instant at which the verdict flips (peak→off-peak or off-peak→peak). Displayed in the visitor's local time. |
| **Local clock** | The visitor's timezone (`Intl.DateTimeFormat().resolvedOptions().timeZone`), used only to display time; never changes the price. |
| **DST** | Daylight Saving Time. Handled automatically via `Intl` conversion; config never stores per-timezone times. |
| **Weekend off-peak** | Saturdays and Sundays in Beijing time (`Asia/Shanghai`, fixed UTC+8) are always off-peak, overriding the peak windows (see `docs/ADR-004`). A fixed second anchor for *which calendar day it is* — never the visitor's own clock. |
| **Cache hit** | Input tokens served from DeepSeek's cache prompt cache; cheapest input price. |
| **Cache miss** | Input tokens not served from cache; priced higher than cache hit. |
| **Output tokens** | Tokens generated by the model; generally the most expensive line item. |
| **1M tokens** | Pricing unit: cost per one million tokens. |
