    Why omp

    oh-my-pi — a coding agent with the IDE wired in

    Complete out of the box

    31 built-in tools · 14 LSP ops · 28 DAP ops · 60+ providers · ~80k lines of Rust core. One terminal session from request to verification — no plugin zoo, no glue scripts.

    omp.sh Docs GitHub

    The short version

    Most terminal agents give the model a shell and a diff format and call it a harness. omp is a fork of Pi by Mario Zechner that keeps the terminal-first UX and adds everything you would otherwise bolt on yourself: language-server-aware edits, a real debugger, structural rewrites, parallel subagents, memory, browser and desktop control — all behind one tool namespace, all in one process, on all three platforms.

    Free credits — $120 to start

    Five reasons to switch

    • 01 · Edits that land first try Hashline patches let the model point at content-hash anchors instead of retyping lines. Stale anchors are rejected before they corrupt a file — no string-not-found retry loops, no whitespace battles.
    • 02 · The IDE is wired in Renames go through workspace/willRenameFiles, so barrel files, re-exports and aliased imports update before the file moves. 14 LSP ops and 28 DAP ops mean it can also attach lldb, dlv or debugpy instead of sprinkling prints.
    • 03 · Native, not shelled out ripgrep, glob, find and a bash fork with 58 in-process coreutils are linked into the binary. No fork/exec on the hot path, no missing rg on a fresh box, and the same binary runs on macOS, Linux and Windows.
    • 04 · Real parallelism + a second opinion task fans work out into isolated worktrees and returns schema-validated results; Agent Hub (Alt+A) lets you steer, revive or kill workers live. An advisor model reads every turn on its own context and flags what the doer rushed past.
    • 05 · Your models, your config, nothing to migrate 60+ providers and ~1000 models across API keys, OAuth, coding-plan subscriptions, gateways and local servers — routed by ten roles (default, smol, slow, plan, advisor…) with fallback chains, path-scoped models and round-robin credentials. On first run it inherits the rules, skills and MCP servers already on disk from .claude, .cursor, .codex, .cline, .windsurf and Copilot. No importer, no migration script.

    omp vs. a plain harness

    What you get in the box versus what you normally wire up yourself.

    Capability Typical agent (opencode, plain Pi) omp
    Editing String replace / unified diff, retry on mismatch Hashline anchors + ast_edit previews
    Code intelligence Text search only LSP: diagnostics, rename, code actions (14 ops)
    Debugging print statements DAP: breakpoints, frames, variables (28 ops)
    Shell & search fork/exec to rg, grep, bash In-process Rust: ripgrep, glob, 58 coreutils
    Parallel work One agent, one context Subagents in isolated worktrees + Agent Hub
    Review Ask nicely, read prose /review with P0–P3 ranking and a verdict
    Pairing Screen share /collab link or QR, client-sealed frames
    Providers A handful, one key each 60+ providers, 10 roles, fallback chains

    Feature claims for omp come from its own README and docs; the middle column describes the common baseline, not a benchmark of any specific release.

    Install it 

    # macOS · Linux
curl -fsSL https://omp.sh/install | sh

# Homebrew
brew install can1357/tap/omp

# Bun (recommended)
bun install -g @oh-my-pi/pi-coding-agent

# Windows (PowerShell)
irm https://omp.sh/install.ps1 | iex

# then, in any repo:
cd path/to/your-project
omp
